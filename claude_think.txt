For the SpscQueue, I'll use a classic implementation:
```cpp
template<typename T, size_t N>
class SpscQueue {
    alignas(64) std::atomic<size_t> head_{0};
    alignas(64) std::atomic<size_t> tail_{0};
    std::array<T, N> buf_;
public:
    bool push(T val) {
        size_t h = head_.load(std::memory_order_relaxed);
        size_t next = (h + 1) % N;
        if (next == tail_.load(std::memory_order_acquire)) return false;
        buf_[h] = std::move(val);
        head_.store(next, std::memory_order_release);
        return true;
    }
    bool pop(T& val) {
        size_t t = tail_.load(std::memory_order_relaxed);
        if (t == head_.load(std::memory_order_acquire)) return false;
        val = std::move(buf_[t]);
        tail_.store((t + 1) % N, std::memory_order_release);
        return true;
    }
    size_t size() const {
        size_t h = head_.load(std::memory_order_acquire);
        size_t t = tail_.load(std::memory_order_acquire);
        return (h - t + N) % N;
    }
};
```

- Producer writes to write_pos, increments write_pos

Now let me think about the AudioProcessingChain more carefully.

The chain is:
1. ChannelMapper: select channels from channel_map
2. HighPassFilter: remove DC offset and low-frequency noise
3. Per-channel AEC: echo cancellation (stub)
4. Beamformer: combine channels into single channel
5. NoiseSuppressor: reduce background noise (stub)
6. AGC/VAD: automatic gain control and voice activity detection
7. Resampler: 48k -> 16k

For the HighPassFilter, I'll use a simple first-order IIR:
```
y[n] = alpha * (y[n-1] + x[n] - x[n-1])
alpha = R / (R + 1) where R = sample_rate / (2 * pi * cutoff_freq)
For cutoff = 80 Hz, sample_rate = 48000:
R = 48000 / (2 * pi * 80) ≈ 95.5
alpha = 95.5 / 96.5 ≈ 0.9896
```

For the Beamformer (delay-and-sum), I'll just average all channels:
```
output[n] = (ch0[n] + ch1[n] + ... + chN[n]) / N
```

For the VAD, I'll use energy-based detection:
```
energy = sum(x[i]^2) / N
speech if energy > threshold
```

For the Resampler (48k -> 16k, factor 3), I'll use simple decimation with a 3-tap FIR anti-aliasing filter:

13	- 向上层提供处理后的 PCM 流（唤醒词引擎、ASR 客户端消费）
14	- 接收 PCM 流播放（TTS 合成结果、提示音、媒体音频）
15	- 软件音量、会话优先级、设备管理、热插拔恢复
16	
17	**不负责：**
18	- 唤醒词识别、ASR 识别、NLU、TTS 文本合成
19	- 对话状态机、业务逻辑

65	## 4. 线程模型
66	
67	| 线程 | 调度 | 职责 |
68	|------|------|------|
69	| CaptureThread | SCHED_FIFO | 读硬件，写 CaptureRingBuf |
70	| PlaybackThread | SCHED_FIFO | 拉 Mixer 输出，写硬件，抽 AEC ref |
71	| ProcessingThread | 普通 | DSP 链，分发给消费者 |
72	| ControlThread | 普通 | API 调用、状态机、设备事件串行处理 |
73	| DeviceThread | 普通 | udev 热插拔监听 |
74	| DiagnosticsThread | 普通 | PCM dump、指标上报 |
75	
76	**实时线程硬性约束（CaptureThread / PlaybackThread）：**
77	无 malloc、无磁盘/网络 I/O、无 mutex 竞争、无日志格式化。线程间通信使用 lock-free queue。

81	## 5. 模块职责
82	
83	### 5.1 CaptureManager
84	
85	打开/关闭输入设备，维护 CaptureThread 和 CaptureRingBuf。
86	
87	```
88	采样率: 48000 Hz
89	位深:   int16
90	通道:   由 channel_map 配置（1/2/4/6/8）
91	帧长:   10 ms
92	CaptureRingBuf 容量: 200 ms（20 帧）
93	```
94	
95	### 5.2 AudioProcessingChain
96	
97	运行在 ProcessingThread，从 CaptureRingBuf 消费，输出单通道 16kHz PCM。
98	
99	```
100	Raw Mic PCM (N ch, 48kHz)
101	  → ChannelMapper
102	  → HighPassFilter
103	  → Per-channel AEC          ← 每通道独立消回声
104	  → Beamformer               → 单通道
105	  → NoiseSuppressor
106	  → AGC / VAD
107	  → Resampler (48k → 16k)    ← libsoxr
108	  → FrameDispatcher
109	```
110	
111	依赖：WebRTC Audio Processing（AEC/NS/AGC/VAD）、libsoxr（重采样 + 时钟漂移补偿）。
112	
113	**时钟漂移补偿：** ProcessingThread 每 30 s 测量采集与播放时钟累计差值，超过 ±0.5 ms 时通过 libsoxr 变速重采样对 AEC reference 做轻微拉伸/压缩。
114	
115	### 5.3 FrameDispatcher
116	
117	将处理后的 PCM 帧分发给多个消费者（唤醒词引擎、ASR 客户端、Diagnostics）。
118	
119	每个消费者持有独立队列，队列满时**丢帧**（不阻塞 ProcessingThread），递增该消费者的 `dropped_frames` 计数。
120	
121	```cpp
122	class FrameDispatcher {
123	public:
124	    ConsumerHandle addConsumer(FrameCallback cb, size_t max_queue_depth);
125	    void removeConsumer(ConsumerHandle);
126	    void dispatch(const AudioFrame&);  // called by ProcessingThread
127	};
128	```
129	
130	### 5.4 PlaybackManager
131	
132	接收业务层的 `PlaybackRequest`（PCM 流或文件路径），管理播放队列、暂停、恢复、停止、打断。
133	
134	**Mixer：** 最多 4 路并发，float32 内部精度，混音后转 int16。溢出由 Limiter 处理，Mixer 不做削波。
135	
136	**AEC Reference Tap：** 在 Limiter 之后、写入硬件之前抽取信号，写入 ReferenceRingBuf（500 ms）。
137	
138	### 5.5 FocusManager
139	
140	管理音频焦点、优先级抢占、ducking、恢复策略。不感知具体设备。
141	
142	> **命名说明：** 此为 AudioManager 内部组件，与业务层的 `SessionManager`（多轮对话上下文）无关。
143	
144	```
145	优先级: ALARM > SYSTEM > TTS > PROMPT > MEDIA > BLUETOOTH
146	```
147	
148	| 场景 | 策略 |
149	|------|------|
150	| ALARM 触发 | 抢占所有，独占播放 |
151	| TTS 播放 | MEDIA ducking −12 dB |
152	| PROMPT 播放 | 与 MEDIA 混音 |
153	| TTS 结束 | 恢复 MEDIA |
154	
155	焦点变更通知 AudioRouter，由 AudioRouter 决定路由目标。FocusManager 不感知设备。
156	
157	### 5.6 AudioRouter
158	
159	决定采集输入来源和播放输出目标。由 FocusManager 焦点变更事件驱动。
160	
161	- 支持按播放类型路由到不同设备（如 ALARM 强制路由到内置扬声器）
162	- 外接声卡断开后自动降级到内置声卡
163	
164	### 5.7 VolumeManager
165	
166	软件音量，不修改系统音量。
167	
168	```
169	final_gain = master_gain × stream_gain × session_gain × ducking_gain × mute_gain
170	```
171	
172	对数音量曲线。增益变化在 10 ms 内线性渐变，防止爆音。支持淡入淡出、限幅、配置持久化。
173	
174	### 5.8 DeviceManager
175	
176	枚举设备、查询能力、监听热插拔、自动恢复。
177	
178	**状态机：**
179	
180	```
181	              open()
182	AVAILABLE ──────────────► ACTIVE
183	    ▲                        │ 断开 / xrun 超阈
184	    │ 恢复成功                ▼
185	RECOVERING ◄────────── DISCONNECTED
186	    │ 超最大重试(5次)
187	    ▼
188	  FAILED ──── 手动触发 ──► RECOVERING
189	```
190	
191	- `ACTIVE → DISCONNECTED`：设备断开或 xrun 超阈值
192	- `RECOVERING → AVAILABLE`：重新枚举并验证设备可用
193	- `RECOVERING → FAILED`：指数退避，最大 5 次
194	
195	### 5.9 Diagnostics
196	
197	运行期可开关，运行在 DiagnosticsThread。
198	
199	- dump 原始麦克风、预处理后、AEC reference PCM
200	- 记录 xrun、丢帧、重连次数
201	- 统计各链路延迟和处理耗时
202	- 提供 `HealthStatus` 快照
203

206	## 6. 数据流
207	
208	### 6.1 采集链路
209	
210	```
211	Microphone
212	  → ALSA Backend
213	  → CaptureThread → CaptureRingBuf (200 ms)
214	  → ProcessingThread → ProcessingChain
215	  → FrameDispatcher
216	  → [WakeWord Engine] [ASR Client] [Diagnostics]
217	```
218	
219	### 6.2 播放链路
220	
221	```
222	PlaybackRequest (PCM stream / file)
223	  → FocusManager (焦点仲裁)
224	  → Decoder / PCM Source
225	  → VolumeManager (per-stream gain)
226	  → Mixer (float32, ≤4路)
227	  → Limiter
228	  → AEC Reference Tap → ReferenceRingBuf (500 ms)
229	  → PlaybackThread → ALSA Backend → Speaker
230	```
231	
232	### 6.3 AEC Reference 链路
233	
234	```
235	ReferenceRingBuf (500 ms, 带硬件时间戳)
236	  → DelayCompensator (偏移 aec_reference_delay_ms)
237	  → AEC Processor (per-channel)
238	```
239	
240	**延迟组成：**
241	
242	```
243	total_delay = playback_hw_buffer_delay
244	            + dac_analog_delay        (5~15 ms，硬件固定)
245	            + speaker_to_mic_delay    (声学传播，取决于物理尺寸)
246	            + adc_analog_delay        (5~15 ms，硬件固定)
247	            + capture_hw_buffer_delay
248	```
249	
250	`aec_reference_delay_ms` 静态配置，调试阶段实测确定。硬件批量生产前须重新标定。
251

255	
256	```cpp
257	enum class BackendError {

259	    kDeviceGone   = 1,  // 触发 DeviceManager 恢复流程

262	    kInvalidState = 4,  // 编程错误，通过 quill 记录

264	
265	struct NegotiatedFormat {
266	    int  sample_rate;
267	    int  channels;
268	    int  period_frames;
269	    int  buffer_frames;
270	    bool is_float;
271	};
272	
273	class IAudioBackend {
274	public:
275	    virtual BackendError    openInput(const DeviceConfig&, NegotiatedFormat&) = 0;
276	    virtual BackendError    openOutput(const DeviceConfig&, NegotiatedFormat&) = 0;
277	    virtual BackendError    readInput(AudioFrame&) = 0;
278	    virtual BackendError    writeOutput(const AudioFrame&) = 0;
279	    virtual AudioDeviceList listInputDevices() = 0;

291	
292	```cpp
293	class AudioManager {

311

318	    DeviceList listOutputDevices() const;
319	
320	    // 诊断
321	    HealthStatus health() const;

323	    // 事件订阅（投递到 ControlThread 队列，不在实时线程回调）

344	
345	// 其他
